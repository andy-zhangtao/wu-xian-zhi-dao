# 审法四问

生成之后用四个问题做可维护性审查。对应契约第 1–4 条，并联动第 5–7 条。

启用完整流水线时：本 Skill 是 `audit/README.md` 的 **第四轴**。由 **Auditor**（`plan-auditor`）写入 `audit/cases/<id>.md`；Conductor 不得用「本对话随口四问」代替独立审计 PASS。

## 何时用

- Auditor 裁决前（完整流水线下必做）
- AI 刚完成大段生成或跨文件修改
- 合并 / 开 PR 前
- 感觉「能跑但心里没底」

## 四问（必须逐条回答）

1. **知识重复吗？**  
   同一规则/校验/错误语义是否出现多份？权威来源在哪？

2. **正交破坏了吗？**  
   本轮是否改动了无关模块？耦合是否变差？一次是否动了多个轴？

3. **决策还可逆吗？**  
   是否焊死了框架、SDK、存储、抽象？替换成本如何？

4. **是碰巧能用吗？**  
   失败路径、边界、不变量是否显式？有没有吞异常？关键路径如何验证？

## 步骤

1. 收集审查范围：未提交 diff、PR diff、或用户指定文件。  
2. 逐条回答四问；每条给出 **通过 / 风险 / 违规** 与证据（文件路径）。  
3. 对照契约 5–7：可测性、破窗、是否过早堆厚度。  
4. 只提出 **必要** 修复；按优先级排序。未经同意不要大范围重写。  
5. 若用户要求「修」，按优先级小步改，并保持一次一轴。

## 输出格式

```markdown
## 审查范围
...

## 四问
| 问 | 结论 | 证据 |
|----|------|------|
| 知识唯一 | 通过/风险/违规 | ... |
| 一次一轴 | ... | ... |
| 可逆 | ... | ... |
| 非巧合 | ... | ... |

## 契约 5–7 附检
- 可测：...
- 破窗：...
- 路径 vs 厚度：...

## 修复建议（按优先级）
1. ...
2. ...

## 建议下一步
- [ ] 按建议小步修复
- [ ] 或唤起「破窗重塑」做重构
```

## 禁止

- 用风格偏好替代可判定问题  
- 审查时顺手大重构（先报告，再单独开轮）  
- 无证据的空泛评价（「代码不够优雅」）
