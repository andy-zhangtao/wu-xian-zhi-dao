# 破窗重塑

对应破窗理论 + 持续重构：先修好「碎玻璃」，再让 AI 继续加功能——否则坏结构会被放大复制。

## 何时用

- 命名混乱、死代码、半截抽象、过时注释增多
- 同一业务规则散落多处
- 难测、改一处坏多处
- 准备继续用 AI 生成前，需要先净化上下文

## 步骤

1. **标定破窗**  
   列出具体问题（文件 + 现象），区分：  
   - 破窗（局部脏乱）  
   - 重复知识（DRY 违规）  
   - 耦合（正交破坏）

2. **选定本轮唯一目标**（一次一轴）  
   只选一类：例如「抽出重复校验」或「拆开 X 与 Y 的耦合」或「清理某目录死代码」。  
   本轮不做功能增量。

3. **小步重构**  
   - 保持行为不变；有测试先跑，无测试先补最小保护网再动。  
   - 每步可验证；避免大爆炸式重写。  
   - 新抽象必须有第二个真实调用点，否则不做「未来也许用得上」的抽象。

4. **验收**  
   - [ ] 行为未改（测试或等价检查通过）  
   - [ ] 重复/破窗/耦合确有减少  
   - [ ] diff 可读、可回滚

5. **交给下一轮生成**  
   用干净结构作为后续 AI 上下文；必要时再唤起「曳光探路」加功能。

## 输出格式

```markdown
## 破窗清单
- ...

## 本轮唯一目标
...

## 重构步骤
1. ...
2. ...

## 验证
...

## 有意未做
...

## 建议下一轮
- 加功能：... / 或继续重构：...
```

## 禁止

- 重构顺带加需求  
- 无第二个用例就引入新框架级抽象  
- 在无验证手段时大范围移动代码  
- 一次清理整个仓库（应拆多轮）
