# 《悟仙之道》

把《程序员修炼之道》（*The Pragmatic Programmer*）压缩成 **AI 可执行的护栏与工序**：薄契约始终生效，短 Skill 按需触发。

目标：缓解「开始简单，越开发越难维护」——尤其是 AI 高速生成带来的熵增。

## 结构

```text
悟仙之道/
├── AGENTS.md                          # 总览与用法
├── .cursor/
│   ├── rules/
│   │   └── wuxian-contract.mdc        # 始终生效的契约法则
│   └── skills/
│       ├── 曳光探路/SKILL.md          # Tracer Bullets：先通路径
│       ├── 审法四问/SKILL.md          # 生成后按四问审查
│       └── 破窗重塑/SKILL.md          # 小步重构、去熵
└── LICENSE
```

## 怎么用

### 方式一：整仓作为 Cursor 规则来源

1. Clone 本仓库，或把 `.cursor/` 拷进你的项目。
2. 打开项目后，契约 `wuxian-contract.mdc` 会作为 Rule 约束生成行为。
3. 需要工序时，让 Agent 读取对应 Skill（或在对话里点名「按曳光探路 / 审法四问 / 破窗重塑」）。

### 方式二：只取契约

只复制 `.cursor/rules/wuxian-contract.mdc` 到你项目的 `.cursor/rules/`。

### 方式三：按任务唤起 Skill

| 时机 | Skill |
|------|--------|
| 新功能、方向未定时 | `曳光探路` |
| AI 大段生成之后 | `审法四问` |
| 感到难维护、重复增多时 | `破窗重塑` |

## 设计原则

| 形态 | 职责 |
|------|------|
| **契约** | 每次生成都不能踩的线（否决权） |
| **Skill** | 有步骤的正确顺序（工序） |

不要做成一本厚 Skill 替代契约；也不要只写鸡汤法则却没有验收动作。

## 与原书的对应（摘要）

- DRY / 知识唯一 → 契约第 1 条  
- 正交性 → 契约第 2 条（一次一轴）  
- 可逆决策 → 契约第 3 条  
- 不靠巧合编程 → 契约第 4 条  
- 为测试而设计 → 契约第 5 条  
- 破窗理论 → 契约第 6 条  
- 曳光弹 → Skill「曳光探路」  
- 重构 / 熵增控制 → Skill「破窗重塑」
